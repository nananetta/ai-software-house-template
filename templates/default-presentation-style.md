# Default Presentation Style

Use this file as the default visual style guide for all investor, product, strategy, business, technical, and internal presentation decks unless a product-specific or CEO-approved deck style overrides it.

For requirements presentations, follow `playbooks/document-standards.md` for the business canvas, management content, single-file HTML packaging, and client-side PlantUML requirements. Keep all decks concise.

## Core Principle

Presentations should be clean, direct, and highly readable. The default look is white, minimal, and structured, with red used as the primary accent. Visual elements should support the message rather than decorate the slide.

## Background

- All slides must use a white background by default.
- Avoid dark full-slide backgrounds unless the CEO explicitly requests a special closing, divider, or dramatic slide.
- Do not use gradient, textured, patterned, or decorative backgrounds by default.

## Color Palette

### Required Default Colors

| Role | Color | Hex |
|---|---:|---|
| Background | White | `#FFFFFF` |
| Primary accent | Red | `#ED1B2E` |
| Secondary accent | Grey | `#898989` |
| Limited text / emphasis | Black | `#000000` |

### Optional Supporting Colors

Use these only when they add meaning, such as status, categories, charts, or diagrams.

| Role | Color | Hex |
|---|---:|---|
| Warning / highlight | Yellow | `#FFD200` |
| Information / system | Blue | `#018ED7` |
| Success / positive | Green | `#62B762` |

Note: If a requested color conflicts with this guide, the red `#ED1B2E` remains the default primary accent.

## Color Usage Rules

- Use red `#ED1B2E` for key emphasis, section markers, selected chart elements, callout rules, and important numbers.
- Use grey `#898989` for secondary text, labels, captions, axes, source notes, dividers, and inactive elements.
- Use black `#000000` sparingly for main titles, critical emphasis, or high-contrast body text.
- Keep most slides visually light. Red should accent the story, not dominate the whole slide.
- Avoid introducing additional colors unless the slide needs clear semantic distinction.

## Typography

- Use a clean sans-serif typeface by default.
- Titles should be concise, claim-led, and easy to read from a distance.
- Body text should be short and structured. Avoid dense paragraphs.
- Use strong hierarchy:
  - Large title
  - Medium subtitle or key claim
  - Small labels, captions, and sources
- Avoid decorative fonts, excessive bolding, and all-caps paragraphs.

## Layout

- Prefer generous white space.
- Use left-aligned text by default.
- Every slide must have a clear topic as the main agenda.
- Every slide must include a one-line sub-agenda directly below the topic.
- Use thin grey dividers or red accent rules instead of heavy boxes.
- Avoid card-heavy slides unless cards are the clearest way to compare repeated items.
- Keep layouts consistent across the deck, but avoid making every slide look identical.
- Every slide should have one main message and one dominant proof object.

## Icons

- Every slide should include at least one picture or icon.
- Super minimalistic icons are encouraged to keep slides from feeling too plain.
- Icons should be simple line icons or minimal filled icons.
- Use icons only when they clarify a concept, workflow, category, or action.
- Default icon color should be grey `#898989`; red `#ED1B2E` may be used for the most important icon on a slide.
- Avoid colorful icon packs, illustrated mascots, 3D icons, emojis, or decorative icon clutter.

## Pictures And Visuals

- A slide may use a relevant picture when it helps explain the agenda.
- If a picture is not necessary, use a minimal icon instead.
- Pictures should be clean, relevant, and secondary to the slide message.
- Do not use generic stock imagery that weakens clarity.
- Product, workflow, system, finance, and technical slides may use icons, diagrams, charts, or simple visual objects instead of photography.

## Charts And Diagrams

- Charts should use white backgrounds, direct labels, and minimal gridlines.
- Use grey for axes, baselines, and supporting series.
- Use red for the main data series or key takeaway.
- Use blue, green, or yellow only when multiple categories need clear semantic distinction.
- Diagrams should use simple shapes, thin lines, and clear labels.
- Avoid unnecessary shadows, gradients, thick borders, and heavy fills.

## Source Notes And Footers

- Use small grey text for source notes.
- Place sources consistently, usually bottom-left.
- Use page numbers only when helpful, usually bottom-right in grey.
- Do not let source notes compete with the main message.

## Do Not Use

- Non-white default slide backgrounds
- Large decorative gradients
- Heavy drop shadows
- Busy illustration styles
- Excessive icon usage
- Multi-color palettes without semantic purpose
- Dense paragraphs
- Red as a full-slide fill unless explicitly approved

## Default Slide Checklist

Before finalizing any slide, verify:

- Background is white.
- Slide has a clear topic as the main agenda.
- Slide has a one-line sub-agenda below the topic.
- Red `#ED1B2E` is the primary accent.
- Grey `#898989` supports labels, dividers, and secondary text.
- Black `#000000` is used only where strong contrast is needed.
- Any extra color has a clear meaning.
- The slide includes at least one relevant picture or minimal icon.
- Icons are minimal and useful.
- The slide has one clear message.
- Text is readable and not crowded.
- The layout feels clean, simple, and professional.
